# سيرفر Webhook: AppSheet → واتس اب مباشرة (whatsapp-web.js)

هذا السيرفر بيشغّل جلسة واتس اب ويب حقيقية جوه السيرفر، وبيستقبل طلبات من AppSheet لإرسال رسائل لأي رقم مباشرة، **بدون أي حساب Meta أو خدمة خارجية مدفوعة**.

---

## ⚠️ تحذيرات مهمة قبل ما تبدأ (اقرأها كاملة)

1. **خطر حظر الرقم:** هذه طريقة غير رسمية (مش معتمدة من واتس اب). لو استخدمتها لإرسال رسائل لعدد كبير من المرضى بسرعة أو بشكل متكرر يوميًا، واتس اب ممكن يعتبره سبام ويوقف الرقم. **نصيحة:** استخدم رقم واتس اب ثانوي (مش رقمك الشخصي الأساسي)، وأضف تأخير بين كل رسالة والتانية (موجود في الكود أساسًا فرصة لإضافته لاحقًا لو حبيت ترسل رسائل بالجملة).

2. **يحتاج تخزين دائم (Persistent Storage):** الجلسة (بعد ما تعمل مسح QR مرة واحدة) بتتخزن في مجلد على القرص. **معظم الاستضافات المجانية (زي Render Free) بتمسح القرص عند كل إعادة تشغيل**، يعني هتضطر تعمل مسح QR من جديد باستمرار. لذلك:
   - الأفضل: **Railway** (بيدعم Volumes/تخزين دائم بسهولة)
   - أو **VPS خاص بيك** (الأكثر استقرارًا لهذا النوع من السيرفرات)
   - Render يحتاج خطة مدفوعة (Persistent Disk) عشان يشتغل صح مع هذه الطريقة.

3. **يحتاج موبايل شغال ومتصل بالنت باستمرار** (نفس مبدأ واتس اب ويب العادي) — لو الموبايل قفل النت لفترة طويلة أو الواتس اب اتفتح على جهاز تاني، ممكن الجلسة تنفصل وتحتاج تعيد المسح.

---

## الخطوة 1: رفع السيرفر على Railway (موصى به لأنه بيدعم تخزين دائم)

1. ارفع هذا المجلد كمستودع على GitHub.
2. ادخل https://railway.app وسجل حساب.
3. **New Project > Deploy from GitHub repo** واختر المستودع.
4. من تبويب **Variables** أضف:
   - `WEBHOOK_SECRET` = اختار كلمة سر قوية
5. من تبويب **Settings > Volumes**: أضف Volume جديد واربطه بالمسار:
   ```
   /data
   ```
   (ده هيخلي مجلد جلسة واتس اب يفضل محفوظ حتى بعد أي إعادة تشغيل)
6. Deploy. بعد الانتهاء هتاخد رابط مثل:
   `https://your-app-name.up.railway.app`

## الخطوة 2: ربط رقم الواتس اب (مرة واحدة فقط)

1. افتح الرابط:
   ```
   https://your-app-name.up.railway.app/qr
   ```
2. هيظهرلك QR Code.
3. من موبايلك: واتس اب > الإعدادات (⋮) > **الأجهزة المرتبطة** > **ربط جهاز**، وامسح الكود.
4. بعد ثوانٍ، لو أعدت فتح `/qr` هتشوف "متصل ✅".

> **ملاحظة:** طول ما القرص Persistent (Volume) مربوط صح، مش هتحتاج تعيد المسح إلا لو فصلت الجهاز يدويًا من موبايلك أو تغيرت بيانات الجلسة.

## الخطوة 3: إعداد Webhook في AppSheet

1. **Automation > Bots** → أنشئ Bot أو استخدم موجود.
2. أضف Step: **"Call a webhook"**.
3. الإعدادات:
   - **URL:**
     ```
     https://your-app-name.up.railway.app/webhook/appsheet?secret=YOUR_SECRET
     ```
   - **HTTP Method:** POST
   - **Content Type:** application/json
   - **Body:**
     ```json
     {
       "phone": "<<[رقم الهاتف]>>",
       "message": "<<[نص الرسالة]>>"
     }
     ```
     (بدّل أسماء الأعمدة حسب جدولك الفعلي، مثلاً من جدول "الوارد" أو "صفحة المرضى")

رقم الهاتف يجب أن يكون بصيغة دولية بدون "+"، مثال: `970599999999`

## تجربة يدوية (Postman أو curl)

```bash
curl -X POST "https://your-app-name.up.railway.app/webhook/appsheet?secret=YOUR_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"phone": "970599999999", "message": "رسالة تجريبية"}'
```

## أخطاء شائعة

- **503 "واتس اب غير متصل":** لسه محتاج تمسح QR من `/qr`.
- **404 "الرقم غير مسجل":** الرقم المدخل مش عليه واتس اب أصلاً أو الصيغة غلط.
- **401 Unauthorized:** المفتاح السري في الرابط غلط.
- **الجلسة بتنفصل باستمرار:** غالبًا القرص مش Persistent (تأكد من إعداد Volume في Railway)، أو الموبايل قافل النت كتير.

## التشغيل محليًا (للتجربة فقط)

```bash
npm install
WEBHOOK_SECRET=test123 npm start
```
ثم افتح `http://localhost:3000/qr` من المتصفح.
